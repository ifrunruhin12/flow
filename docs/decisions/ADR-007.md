# ADR-007: Individual Playback Persistence and Browser Transport

- **Status:** Accepted for M3
- **Date:** 2026-11-06
- **Scope:** FR-IND-001…006 only

## Context

The reconciled baseline requires one PostgreSQL session per account, immediate
command persistence, and revision CAS. Its individual session omitted play/pause
intent, and its three REST routes did not define queue edits, next/previous,
checkpoint identity guards, or queue edge cases. Architecture summaries also
named a server hot cache, Zustand, and PATCH despite the accepted PUT contract
and the existing React context architecture. None is needed for M3.

## Decision

- Keep GET, PUT, and DELETE `/api/playback/session`. Extend PUT additively with
  `status`, `queueEdit`, and `command`; the full contracts live in API §4 and
  PLAYBACK_SYSTEM §2. No per-device rows, new control service, or WebSockets.
- Persist `playback_status` (`paused`/`playing`) as transport **intent**. Restored
  intent never starts browser audio automatically. Actual transport status is
  local, and autoplay rejection is surfaced and checkpointed as paused.
- Read PostgreSQL directly. Apply every mutation using conditional revision
  UPDATE, with an account/session recheck in the commit transaction. Neither an
  in-memory cache nor an unprotected read/write is authoritative.
- A user-insert trigger creates the default session in the same transaction;
  migration backfills existing accounts. DELETE clears content through CAS and
  retains the row, revision, volume, and shuffle.
- Keep the canonical queue unchanged by shuffle. Derive a stable permutation
  from each occurrence's media ID and server-added timestamp. No repeat mode or
  automatic conflict merge. Preserve occurrence identity across move/removal.
- One React provider owns one controller and one audio element for the signed-in
  account. The controller serializes requests and reconciles to the returned
  snapshot on 409; pending stale actions and failed checkpoints are not retried.
  No additional frontend state dependency is needed.
- Removing historical occurrences never requires the retained destination to be
  available in Navidrome. Its deterministic successor/predecessor remains in the
  queue; a failed metadata/audio load pauses local transport and saves paused
  intent. Explicit selection and new entries still require accessible media.
- Natural end waits for this browser's earlier pending commands, then checks the
  captured occurrence before sampling the dispatch revision/index. This avoids
  a self-conflict after an unrelated volume/checkpoint write. An external change
  or 409 discards the event; it is never replayed after reconciliation.
- Stream failure saves the actual stopped position. Explicit retry cancels and
  reloads the failed gateway source before attempting audio again.
  A rejected or discarded stopped-intent callback cannot restore its old stream
  error over a reconciled snapshot or a replacement source.
  Pausing retained media remains possible when metadata is missing or temporarily
  unavailable; the absolute position bound still applies, with duration checks
  whenever member-scoped metadata can be read.
- Checkpoint actual media position every 10 seconds while playing, plus pause,
  seek, transition, and natural end. Checkpoints include sampled track and queue
  index, as well as the sampled revision. Restore the durable position without
  an age cutoff; reset to zero only at/beyond a known duration.
- Refresh REST state every 15 seconds and on focus/visibility/online. A newer
  snapshot pauses this browser and restores state without auto-playing. This
  fences stale persistence, not concurrent audio on separate devices.

## Consequences

No command is considered saved until its CAS commits. A crash can lose progress
since the last acknowledged checkpoint; background timer throttling and network
loss can extend that window. A stale checkpoint cannot overwrite a track change.
Unavailable retained queue items remain removable; selecting or adding missing
media is rejected through the member-scoped library adapter. There is no atomic
transaction spanning PostgreSQL and Navidrome, so media can disappear after
validation and is also checked by the existing audio gateway.

M4 state, DJ authority, event protocols, and synchronized transport are untouched.
