# Flow — Security

Version: 1.0.0-draft
Threat posture: A-003/A-004 from REQUIREMENTS — trusted LAN operator, invited members, internet edge at Caddy. The design goal: **no client, including an adversarial member, can exceed the permissions of their Flow role, even if they reach the stack with custom tools.**

---

## 1. The Threat Model (explicit, so decisions are defensible)

| Threat | Actor | Mitigation (section) |
|---|---|---|
| Member guesses/reaches Navidrome's API | any authenticated member | Navidrome has **no public ingress** (§2) |
| Member crafts raw HTTP to Flow's admin endpoints | member with valid credentials | Role-gated routes + per-route role middleware; admin endpoints 403 for members even with a valid Flow JWT (§3) |
| Member intercepts/forwards a stream URL | member | URLs are per-user, user-scoped JWT, 15-min cap; forwarding only grants *their own* read/stream level (§4) |
| Request forgery / XSS → account takeover | external | Same-site cookie, CSRF-safe API (Authorization header primary; cookie is `SameSite=Lax`, `Secure`, `HttpOnly`), strict CSP, no `innerHTML` for user data (§5) |
| Brute-force on Flow login or register-request spam | external | Rate limits (§6) |
| Path traversal / malicious file in upload | admin only (uploads are admin-only) | Path validation + extension allowlist + size cap; files land in the music volume but are *indexed by Navidrome*, so a bad file affects playback, not the system (§7) |
| Credential leakage via logs | ops | No credentials/URLs-with-jwt in logs; redaction middleware; request logging without query strings on stream routes (§8) |
| Supply chain: Flow backend image | ops | Pinned Go image multi-stage build, minimal base (distroless), SBOM + `trivy` in CI (§9) |
| DB dump | host-level, out of scope but noted | `navidrome_password_enc` is AES-GCM under a key held **only** in env (`FLOW_NAVIDROME_KEY`); a DB copy without the key is not usable for Navidrome access (§4) |

## 2. Network Topology = Primary Control

```
Internet ──► Caddy:443 (TLS/ACME)
               ├── /        → flow-web (static)
               ├── /api     → flow-backend:8080
               ├── /ws      → flow-backend:8080/ws
               └── (navidrome: no route. period.)
Docker internal network (no host-published ports):
               flow-backend:8080 ──► navidrome:4533 ──► postgres:5432
               flow-backend ──► /music volume (rw)
               navidrome ──► /music volume (ro)
```

- **Navidrome publishes zero ports** and has no route in the Caddyfile. The only path to Navidrome HTTP is through the Flow backend, which is itself the only process holding admin credentials.
- Consequence: a member can only ever talk to Flow. "Bypass Flow and hit Navidrome directly" is not possible from the network, not by luck or by finding the internal DNS name (container DNS is not resolvable from outside the compose network).
- This is the answer to "members must never gain administrative access through direct API requests or by bypassing the Flow frontend": **they physically cannot reach an admin endpoint, and every admin operation Flow performs requires the admin Flow JWT, which members don't have.**

## 3. Authorization Architecture (Flow backend)

Three-layer enforcement (defense in depth; every layer is cheap):

```
L1  Middleware auth:  verify Flow JWT → attach User{role, status} to context
                      (status=suspended → 403 immediately, every route)
L2  Route group gates:
      /api/auth/*            — anonymous allowed (login, register-request)
      /api/library|playlists|playback|sync|streams|themes — any ACTIVE user
      /api/admin/*           — admin only  (chi group + RoleAdmin)
      /api/platform/mode     — admin write, all-user read
L3  Domain checks: services re-assert the invariant (e.g., sync mutations
      require role==admin *and* are DJ-only when a session is active).
```

- No endpoint trusts a client-supplied `role`. The role comes from the DB row bound to the verified JWT.
- WebSocket: same JWT on the upgrade (`Authorization` header, `Cookie` fallback). The WS hub checks L1 on connect and L2 on every control-message type (`sync-*` control messages: admin only — enforced in the message dispatch table, not just the HTTP route).
- **Members cannot escalate**: the only writes that change roles are `/admin/users` (admin-gated) and the bootstrap path (env-var gated, runs once, no API surface).

## 4. Credential Isolation (Navidrome side)

Verified facts driving this (see NAVIDROME_INTEGRATION.md §3):

1. Members' Navidrome accounts: passwords generated by Flow (`crypto/rand`, 32 B). Stored as `AES-GCM` under `FLOW_NAVIDROME_KEY` (env, 64-hex, never in the image, rotated by re-provisioning).
2. The admin's Navidrome credentials: same treatment.
3. Navidrome JWTs: cached in memory only (`map[user]→{jwt, expiresAt}`), evicted on suspend/delete, never logged, never serialized to disk.
4. **On approve:** Flow creates the member in Navidrome via the native user API (Subsonic's `createUser` is 501 Not Implemented in Navidrome — see NAVIDROME_INTEGRATION §4), sets `isAdmin: false`, and links Flow user ↔ Navidrome user. From then on, every member-facing call (browse/search/stream) uses **the member's own** Navidrome credentials — admin credentials appear in no member-facing response, URL, or log.
5. Stream URLs given to members embed the **member's own** JWT. Max useful life = Flow's 15-minute issuance window; Navidrome JWT refresh happens server-side, so the client never learns of or controls renewal.
6. Navidrome config: `enableSharing=false`, `enableDownloads=false` (**compose must set `ND_ENABLEDOWNLOADS=false` explicitly — it defaults to `true` in Navidrome**), `enableArtworkUpload=false` (**same — defaults to `true`**), both verified in `conf/configuration.go` — no anonymous public surface (`/share/*` would be reachable if sharing were on; it is not exposed anyway, but the flags are belt-and-braces).

The invariant, testable end-to-end: **an attacker who fully compromises a member's device and captures every URL and token the member's app ever saw can at worst stream that member's library access for ≤15 minutes, as that member, read-only.**

**Deploy invariant:** Navidrome's `ND_ENABLEDOWNLOADS` and `ND_ENABLEARTWORKUPLOAD` must be set to `false` explicitly in the compose file (both default to `true` in Navidrome — verified in `conf/configuration.go`). With downloads enabled, a captured stream URL upgrades to full-quality original download rights (the `download` Subsonic endpoint honors the same user JWT) — which would break the V1 "members cannot download" requirement. V1.x (M10): per-request stream proxy tokens replace embedded JWTs and close the 15-minute capture window entirely.

## 5. Web Client Hardening

- Cookie: `HttpOnly`, `Secure`, `SameSite=Lax`, path `/`.
- API primary auth: `Authorization: Bearer` (in-memory token in the SPA session, not persisted to localStorage — page reload re-fetches via the cookie).
- CSP: `default-src 'self'; connect-src 'self' wss://<domain>; img-src 'self' data:; style-src 'self' 'unsafe-inline'` (Tailwind output is self-contained; revisit if a CDN ever enters).
- All user-supplied strings rendered as text (React default); no `dangerouslySetInnerHTML`.
- Register-request endpoint is anonymous: it is the only one; body-validated, no PII beyond name/email/username; no account exists until approval (no pre-provisioned password, no link-claiming — approval creates the credential).

## 6. Rate Limiting

| Surface | Limit | Where |
|---|---|---|
| `/auth/login` | 10 / 15 min / IP **and** 20 / 15 min / username | Flow middleware (token bucket, in-memory; single instance ⇒ fine) + Navidrome's own `authrequestlimit` as backstop |
| `/auth/register-request` | 3 / 24 h / IP, 1 open pending per email | Flow |
| Uploads | size cap per file (admin-set, default 500 MB), batch cap 100 files | Flow middleware |
| Sync heartbeats | per-connection min interval 2 s (drops+warns beyond) | WS hub |
| Library proxy | inherit Navidrome throttling; Flow adds a soft 30 req/s/user burst limiter to prevent one tab from starving the proxy | Flow |

## 7. Upload Validation (admin route)

- Route: admin-only. Member upload attempts are 403 before any body read.
- Path: `albumPath` sanitized — each segment must match `^[A-Za-z0-9 _\-()\.\[\]]+$`, no `..`, no leading `/`, total depth ≤ 3, final component must be a file with an allowed extension (FLAC/MP3/M4A/AAC/OGG/MP4/WAV + Navidrome's indexable set; the list is generated from Navidrome's `mime_types.yaml` at build time to stay in sync).
- Body: streaming write (never buffer the whole file); `Content-Length` enforced ≤ cap; abort + partial-file cleanup on any error.
- After write: checksum-optional (V1: skip); Navidrome's scanner re-verifies/reads tags.
- Malicious-content note: a corrupted FLAC in the volume makes *that* track unplayable, not the platform. No execution path from media content into the backend (streaming is Navidrome's concern; Flow never execs media).

## 8. Logging and Secrets

- `slog` JSON; levels via `FLOW_LOG_LEVEL`.
- Redaction middleware: on `/streams/*`, `/auth/*` (password), `/admin/uploads` — log method+path+status+duration only, no query/body.
- `FLOW_NAVIDROME_KEY`, `FLOW_ADMIN_PASSWORD`, DB DSN: env only; compose `env_file` is `chmod 600`, never in the image, never in git (a `.env.example` with empty values is committed).
- Audit log table for admin actions (DATABASE_SCHEMA §2.9) is the compliance trail; it never contains credentials.

## 9. CI / Image Hygiene

- Backend: `golang:1.22-alpine` → `distroless/static` (or `alpine` with non-root user); no shell in final image (alpine base includes busybox; document trade-off).
- `trivy` scan on both images in CI; Dependabot on Go modules + npm.
- Migrations: `up` in CI against a disposable Postgres; `down` not required for releases (ops runs fresh or forward).
- Secrets in CI: none needed for V1 (no live Navidrome in CI); integration tests use testcontainers.

## 10. Backup and Recovery

| Asset | What | How |
|---|---|---|
| `music/` volume | **the irreplaceable asset** | Operator's existing backup (NAS snapshot / rsync to cold storage). Flow never rewrites originals. |
| Flow Postgres | users, sessions, audit | `pg_dump` nightly (compose `backup` sidecar or host cron); restore = new cluster + run migrations |
| Navidrome data | SQLite index + cache | `pg_` — no: `nd_data` volume copy while Navidrome stopped; index is rebuildable by re-scan (documented: worst case = drop the volume, re-scan) |
| `FLOW_NAVIDROME_KEY` | key for member password ciphertexts | With the Postgres dump, in the same encrypted backup location |

Recovery drill (documented in DEPLOYMENT.md): restore flow-pg + key → boot → backend re-logs into Navidrome per member lazily; members' Navidrome accounts survive because they live in Navidrome's own DB (restore that too, or re-provision from the key).

## 11. Security Acceptance Tests (implemented as e2e)

1. Member token → every `/admin/*` and `POST /platform/mode`: **403**. (Route table assertion test, all admin routes.)
2. Member token → WS `sync-play`: **rejected by dispatch** (event `error: forbidden`), no state change.
3. Suspended member: stored Flow token stops working within 1 s (revocation check per request — the JWT carries a `jti` checked against the in-memory revocation set, persisted only at logout/suspend time).
4. `curl` any Navidrome port on the host: **connection refused** (compose publishes none) — a deployment test.
5. Captured stream URL replayed after 15 min: **403/401** (Navidrome rejects the expired/refreshed token mismatch).
6. Compose config check: assert `ND_ENABLEDOWNLOADS=false` and `ND_ENABLEARTWORKUPLOAD=false` are in effect on the running Navidrome (read back via `GET /api/config` from inside the network); fail the deployment test if either is `true`.
7. Upload route with a member token: **403**, body not read.
